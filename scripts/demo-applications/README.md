# ข้อมูลใบสมัครตัวอย่างสำหรับสาธิตต่อคณะกรรมการ

สร้างข้อมูลจริงในฐานข้อมูล (ไม่ใช่โหมดสาธิตแบบอ่านอย่างเดียวของ Excellence) เพื่อให้ช่วงใบสมัคร → ตรวจหลักฐาน → ประกาศผล ใน `docs/COMMITTEE_DEMO.md` สาธิตได้

## ใช้งาน

```bash
node scripts/demo-applications/seed-applications.mjs seed scripts/demo-applications/accounts.local.txt
```

```bash
node scripts/demo-applications/seed-roster.mjs seed
```

```bash
node scripts/demo-applications/seed-excellence.mjs seed
```

รันตามลำดับนี้ เพราะ roster และผลสมรรถภาพอ้างใบสมัคร · รหัสผ่านที่สุ่มให้ถูกเขียนลง `accounts.local.txt` ซึ่ง gitignore ไว้แล้ว ทุกบัญชีตั้ง `mustChangePassword` เป็นจริง

## ลบทิ้งหลังนำเสนอ

```bash
node scripts/demo-applications/seed-excellence.mjs cleanup
```

```bash
node scripts/demo-applications/seed-applications.mjs cleanup
```

`seed-applications cleanup` ลบ roster และผลสมรรถภาพ/ผลแข่งที่ค้างให้เองด้วย จึงไม่ต้องสั่ง `seed-roster cleanup` แยก

`cleanup` ของ `seed-applications` ลบไฟล์ในที่เก็บเอกสารส่วนตัวด้วย และพิมพ์จำนวนแถวที่เหลือ (ต้องเป็น 0 ทุกช่อง) · `seed` เรียก `cleanup` ให้เองก่อนสร้างใหม่ จึงรันซ้ำได้

## ข้อควรรู้

- ไม่แก้ schema และไม่รัน migration ใด ๆ เขียนเฉพาะข้อมูลด้วย SQL ผ่าน `pg` และอัปโหลดไฟล์ด้วย service role key จาก `.env`
- ถ้ากดอนุมัติ/ไม่อนุมัติ/ประกาศผลตอนซ้อม สถานะจะเปลี่ยนจริง ให้รัน `seed` ใหม่เพื่อคืนสถานะตั้งต้น
- เอกสารเป็น PDF/PNG เปล่าที่มีข้อความ "DEMO DOCUMENT - NOT A REAL RECORD" ไม่ใช่เอกสารของบุคคลจริง
- กีฬาประเภทบุคคลใช้สถานะ roster `selected` ไม่ใช่ตัวจริง/สำรอง ปัจจุบันหน้าชมรมขึ้น "ผ่านการคัดเลือก N คน" และป้าย "ชมรมเสนอชื่อ" และหน้าสถานะของนักกีฬาก็ขึ้น "ชมรมเสนอชื่อ" เช่นกัน (เดิมขึ้น "ตัวจริง 0 คน · ตัวสำรอง 0 คน" และ "ยังไม่ได้ระบุ" ซึ่งแก้แล้ว)

## ข้อมูลสู่ความเป็นเลิศ (`seed-excellence.mjs`)

หน้าสู่ความเป็นเลิศอ่านเฉพาะใบสมัครกรีฑาที่สถานะ `STAFF_APPROVED` หรือ `FINAL_SELECTED` (`lib/excellence-service.ts`) จึงมีนักกีฬา 4 คนในรายงาน ไม่ใช่ 6 คน · นางสาวจิรารัตน์ (ตก GPAX) และนายธีรภัทร (รอกองกิจฯ) ไม่ปรากฏ ซึ่งถูกต้องตามกฎ

| สิ่งที่สร้าง | รายละเอียด |
|---|---|
| ผลทดสอบสมรรถภาพ | `FitnessTestResult.scores.items` เก็บ **ตัวเลขดิบ** ของทั้ง 11 สถานีตามคีย์กลุ่ม 9 ระบบตัดระดับเองตามเพศด้วย `rateGroup9Value` ไม่ได้เก็บข้อความระดับไว้ล่วงหน้า |
| ผลแข่ง | `CompetitionMatch` + `CompetitionMatchEntry` · ลู่ = TIMED + `timeSeconds`, ลาน = RANKING + `score` · match แยกตามรายการ + ประเภท + วัน + รอบ |
| เป้าหมาย | 4 คีย์ใน `SystemSetting` คีย์ `ATHLETICS_TRACK_BENCHMARKS` (100 ม. ชาย 11.00 / 100 ม. หญิง 12.60 / 400 ม. หญิง 1:00.00 / กระโดดไกล ชาย 7.20) · คีย์อื่นที่มีอยู่เดิมไม่ถูกแตะ และ `cleanup` ลบเฉพาะ 4 คีย์นี้ |
| แผนพัฒนา / ทดสอบซ้ำ | `scores._excellence.v2` ของนายเกียรติศักดิ์ (แผน 2 ข้อ + ทดสอบซ้ำที่ดีขึ้นเกิน SWC) และนายชนาธิป (แผนเลยกำหนด ยังไม่ทดสอบซ้ำ) |

สิ่งที่เห็นในหน้าภาพรวมด้วยข้อมูลจริง: นักกีฬา 4 คน · ถึงเป้าหมาย 33% · มีแผนพัฒนา 50% · ทดสอบซ้ำ 1 คน · พัฒนาขึ้นหลังทดสอบซ้ำ 100% และรายการ "ต้องติดตาม" ครบทั้ง 4 แบบ (มีจุดอ่อนแต่ไม่มีแผน 1 · แผนเลยกำหนด 1 · ยังไม่ตั้งเป้า 1 รายการ · ยังไม่มีผลแข่ง 1)

ค่าตัวเลขดิบถูกเลือกให้ได้ระดับที่ต้องการ (คอมเมนต์กำกับไว้ทุกบรรทัดในสคริปต์) ยืนยันแล้วจากหน้าแผนที่จุดอ่อนทีม: นายเกียรติศักดิ์ 2/11 (แรงเหยียดขา ต่ำ, วิ่งเร็ว 40 ม. ต่ำ) · นางสาวกานต์ธิดา 1/11 (แรงบีบมือ ต่ำมาก) · นายชนาธิป 1/11 (นั่งงอตัว ต่ำ) · นางสาวศิริพร 0/11
