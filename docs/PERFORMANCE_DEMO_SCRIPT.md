# Performance Excellence Demo Script

## วัตถุประสงค์

สาธิตว่าระบบสามารถเชื่อมข้อมูลสมรรถภาพก่อนการแข่งขันกับผลการแข่งขัน และนำเสนอข้อมูลประกอบการวางแผนพัฒนานักกีฬาได้ โดยไม่อ้างว่าระบบทำนายผลหรือพิสูจน์สาเหตุของการแพ้ชนะ

## ขอบเขตของ Demo

- กีฬานำร่อง 2 ชนิด:
  1. กรีฑา (รายการวิ่ง 40 เมตร, เวลาเป้าหมาย 5.2 วินาที, คะแนนเป้าหมาย 85)
  2. กีฬาทางน้ำ / ว่ายน้ำ (รายการฟรีสไตล์ 50 เมตร, เวลาเป้าหมาย 27.5 วินาที, คะแนนเป้าหมาย 85)
- นักกีฬาจำลอง: 5 คน (กรีฑา 3 คน, ว่ายน้ำ 2 คน) พร้อมผลทดสอบซ้ำหลังฝึก (Closed Loop) ทั้ง 2 กีฬา
- การวิเคราะห์: Rule-based decision support
- ข้อมูลทั้งหมดเป็นข้อมูลจำลองและไม่ปะปนกับข้อมูลจริง

## ลำดับการนำเสนอ 5-7 นาที

### 1. อธิบายปัญหา

ระบบกีฬาโดยทั่วไปมักหยุดที่การสมัครและการบันทึกผลทดสอบ ทำให้ไม่เห็นว่าข้อมูลก่อนการแข่งขันเชื่อมโยงกับผลการแข่งขันอย่างไร

### 2. แสดงข้อมูลก่อนการแข่งขัน

ชี้ให้เห็นชุดสมรรถภาพนำร่องกรีฑา 7 รายการ และว่ายน้ำ 8 รายการ ค่าเฉลี่ยความพร้อม และ Gap ของนักกีฬาแต่ละคน ไม่ใช้เวลาวิ่งแทนเวลาว่ายน้ำ และไม่เติมระดับผลทดสอบให้รายการที่ไม่มีข้อมูล

### 3. แสดงผลการแข่งขัน

เปรียบเทียบสถิติเวลาจริงกับเวลาเป้าหมายตามชนิดกีฬา:
- กรีฑา: เวลาวิ่ง 40 เมตรเทียบเป้าหมาย 5.2 วินาที
- กีฬาทางน้ำ: เวลาว่ายฟรีสไตล์ 50 เมตรเทียบเป้าหมาย 27.5 วินาที

### 4. แสดงกรณีศึกษาใน 2 กีฬานำร่อง

- กรีฑา Benchmarking: สมรรถภาพสูงและทำเวลาได้ตามเป้าหมาย (5.1s vs 5.2s)
- กรีฑา Speed Gap: ความเร็วและแรงระเบิดต่ำ ช้ากว่าเป้าหมาย (5.7s vs 5.2s)
- กรีฑา Flexibility Risk: ความอ่อนตัวต่ำ เสี่ยงบาดเจ็บ แม้ผลแข่งติดโพเดียม
- ว่ายน้ำ Benchmarking: สภาพร่างกายยอดเยี่ยม ว่ายแตะขอบสระ 26.8s (เร็วกว่าเป้า 27.5s)
- ว่ายน้ำ Endurance Gap: ความอดทนตกช่วง 15 เมตรสุดท้าย (29.8s vs 27.5s)

### 5. แสดงข้อเสนอแนะและผลทดสอบซ้ำ (Closed Loop)

- เปิดการ์ดนักกีฬาเพื่อแสดงจุดแข็ง จุดที่ควรติดตาม และข้อเสนอแนะตามกฎของระบบ
- ที่การ์ด "นาย ภานุพงศ์ วงศ์สว่าง" แสดงผลทดสอบซ้ำหลังฝึก 4 สัปดาห์:
  - ตัวอย่างแผนฝึก: Plyometrics, Resistance Training และฝึกออกตัว
  - เวลาดีขึ้นจาก 5.7s เหลือ 5.4s (เปลี่ยนแปลง -0.3s)
  - คะแนนความพร้อมแบบ composite เพิ่มจาก 52% เป็น 70%
  - ยังช้ากว่าเป้าหมาย 5.2s อยู่ +0.2s จึงต้องติดตามต่อรอบถัดไป
- ที่การ์ด "น.ส. อลิสา ชัยชนะ" (กีฬาทางน้ำ) แสดงผลทดสอบซ้ำหลังฝึก 6 สัปดาห์:
  - แผนฝึก: Aerobic Swim Drills 50m x 8 เที่ยว, Dryland Core & Resistance, และฝึกคุม Stroke Rate
  - เวลาดีขึ้นจาก 29.8s เหลือ 28.2s (เปลี่ยนแปลง -1.6s)
  - ความพร้อมเพิ่มจาก 60% เป็น 78% (เปลี่ยนแปลง +18 คะแนน)
- อธิบายว่าผลนี้เป็นข้อมูลจำลองและไม่พิสูจน์ว่าการเปลี่ยนแปลงเกิดจากแผนฝึกเพียงปัจจัยเดียว

### 6. แสดงภาพรวมโปรแกรม

เลือกมุมมอง "ภาพรวมโปรแกรม" (ใช้นักกีฬาจำลองกีฬาละ 12 คน ไม่ใช่ 5 กรณีด้านบน):
- ความครบของข้อมูล: กี่คนมีผลสมรรถภาพ เวลาแข่ง แผนพัฒนา และผลทดสอบซ้ำ
- สัดส่วนที่ถึงเป้า: เวลา สมรรถภาพ และทั้งสองด้าน เทียบช่วงแข่งกับหลังแผน (กลุ่มเดียวกัน)
- Gap ก่อน → หลังแผน: ค่ากลางและกราฟรายคน
- ความสัมพันธ์รายสถานีกับเวลา: ใช้ตัดสินว่าควรให้น้ำหนักสถานีใดในแผนฝึก
- ต้องบอกผู้ชมว่าความสัมพันธ์ในชุดจำลองถูกกำหนดขึ้นเอง และข้อมูลจริงต้องมีอย่างน้อย 8 คนต่อกีฬาจึงจะแสดงค่า

### 7. สรุปวงจรของระบบ

Baseline สมรรถภาพ -> ผลแข่งขัน -> Gap Analysis -> แผนฝึกของโค้ช -> ทดสอบซ้ำ -> เปรียบเทียบผลและติดตามต่อ

## ข้อความที่ควรใช้ในการนำเสนอ

> ระบบพบแนวโน้มเบื้องต้นจากข้อมูลที่มี และเสนอประเด็นให้โค้ชติดตาม ไม่ได้วินิจฉัยสาเหตุหรือทดแทนผู้เชี่ยวชาญ

## ข้อจำกัด

- ใช้ข้อมูลจำลองเพียง 3 กรณี จึงไม่สามารถสรุปนัยสำคัญทางสถิติได้
- รองรับการสาธิตกีฬาและรายการทดสอบเดียว
- ข้อเสนอแนะสร้างจากกฎที่กำหนด ไม่ใช่โมเดล Machine Learning
- ผลทดสอบซ้ำเป็นข้อมูลจำลองเพื่อสาธิตวงจรปิด ไม่ใช่ผลลัพธ์จากการทดลองฝึกจริง
- ระบบต้นแบบแสดงผลการแข่งขันล่าสุด ไม่ใช่แนวโน้มหลายฤดูกาล
- มุมมองโปรแกรมเปรียบเทียบก่อน-หลังโดยไม่มีกลุ่มควบคุม จึงเป็นการสังเกตแนวโน้ม ไม่ใช่การพิสูจน์ผลของแผนฝึก
