# Project Context

## Project Purpose
University Sports Competition Management System (ระบบบริหารจัดการการแข่งขันกีฬามหาวิทยาลัยพะเยา)
ระบบออกแบบมาเพื่ออำนวยความสะดวกในการลงทะเบียนนักกีฬา การจัดการทีม การตรวจสอบคุณสมบัติ การจัดตารางแข่งขัน การบันทึกผล และการรายงานสถิติสำหรับงานแข่งขันกีฬาภายในมหาวิทยาลัย

## Main Actors & Responsibilities
1. **นักกีฬา (Athlete)**: กรอกประวัติ แนบเอกสาร สมัครแข่งขันเดี่ยว/ทีม ตรวจสอบสถานะการสมัคร
2. **ประธานชมรม (Club President)**: จัดการรายชื่อนักกีฬาในสังกัด อนุมัติ/ส่งใบสมัครของชมรม จัดการข้อมูลโค้ชและตารางซ้อม
3. **เจ้าหน้าที่ทีม / กรรมการ (Team Official / Referee)**: จัดการทีมที่เข้าร่วม สมัครเข้าร่วมในฐานะเจ้าหน้าที่ บันทึกผลการแข่งขัน
4. **เจ้าหน้าที่กองกิจการนิสิต (Staff)**: ตรวจสอบคุณสมบัติ อนุมัติ/ปฏิเสธใบสมัคร คัดเลือกนักกีฬา จัดตารางแข่งขัน
5. **ผู้ดูแลระบบ (Admin/Superadmin)**: ตั้งค่าระบบ จัดการโควตากีฬา จัดการผู้ใช้งาน

## Main Modules
1. **การจัดการการแข่งขัน (Competition Management)**: กำหนดปีการแข่งขัน ชนิดกีฬา ช่วงเวลา และโควตา
2. **การจัดการนักกีฬาและชมรม (Athlete & Club Management)**: จัดการโปรไฟล์นักกีฬา ข้อมูลชมรม โค้ช
3. **การสมัครแข่งขัน (Application)**: การสมัครรายบุคคลและการส่งรายชื่อโดยชมรม (Club Roster)
4. **การตรวจสอบและอนุมัติ (Approval Workflow)**: ตรวจสอบคุณสมบัติตามลำดับขั้น (ชมรม -> เจ้าหน้าที่)
5. **การจัดการเอกสาร (Document Management)**: อัปโหลดและตรวจสอบเอกสารส่วนตัวแบบ Private
6. **สถิติและรายงาน (Analytics & Reports)**: Dashboard สรุปจำนวนผู้สมัครและรายงานผล

## Main Business Flows
- **การสมัครของนักกีฬา**: นักกีฬาสร้าง Profile -> เลือกรายการแข่งขัน -> อัปโหลดเอกสาร -> ชมรมตรวจสอบ (ถ้ามี) -> เจ้าหน้าที่ตรวจสอบ -> คัดเลือกตัวจริง/สำรอง
- **การส่งรายชื่อโดยชมรม (Roster)**: ชมรมรวบรวมใบสมัคร -> จัดการ Squad (ตัวจริง/สำรอง) -> ยืนยันรายชื่อส่งให้กองกิจการนิสิต
- **การจัดการเอกสาร**: อัปโหลดเอกสารเข้าระบบ Private Storage -> ระบบจำกัดการเข้าถึงเฉพาะเจ้าของและผู้มีสิทธิ์ -> อนุมัติ/ปฏิเสธ

## Important Business Rules
- นักกีฬา 1 คน สมัคร 1 รายการแข่งขัน ต่อ 1 ชนิดกีฬา ได้เพียง 1 ใบสมัครเท่านั้น (Unique: `userId`, `competitionId`, `sport`)
- การตรวจสิทธิ์ต้องทำที่ Server เสมอ
- การเปลี่ยนสถานะใบสมัครมีลำดับ: `SUBMITTED` -> `CLUB_APPROVED` (ถ้ามีชมรม) -> `STAFF_APPROVED` -> `FINAL_SELECTED` (กรณีถูกปฏิเสธจะเป็น `CLUB_REJECTED` หรือ `STAFF_REJECTED`)
- ห้ามดัดแปลงหรือสร้างข้อมูลสถิติปลอม Analytics ต้องอ้างอิงจากข้อมูลใบสมัครจริง

## Main Data Concepts (Terminology)
*(Actual model names must follow the current Prisma Schema)*
- **User**: ผู้ใช้งานระบบ (ผูกกับ **AthleteProfile** แบบหนึ่งต่อหนึ่ง)
- **Club**: บัญชีองค์กรชมรมกีฬา (มีอีเมลและรหัสผ่านแยกต่างหาก)
- **Competition**: รายการแข่งขันกีฬา
- **SportQuota**: โควตาจำนวนรับสมัครแต่ละประเภทกีฬา
- **Application**: ใบสมัครเข้าร่วมการแข่งขันของนักกีฬา
- **ClubRoster**: บัญชีรายชื่อที่ชมรมรวบรวมเพื่อส่งเข้าร่วมการแข่งขัน
- **RosterItem**: รายการใบสมัครที่อยู่ใน ClubRoster
- **PrivateDocument**: เอกสารส่วนบุคคลที่มีการจำกัดสิทธิ์การเข้าถึง (เก็บใน Supabase Storage)
- **AnalyticsSnapshot**: ข้อมูลสรุปสถิติที่ถูกบันทึกไว้ ณ เวลาใดเวลาหนึ่ง (คำนวณโดย server)
